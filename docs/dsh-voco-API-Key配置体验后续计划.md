# dsh-voco API Key 配置体验后续计划

## 背景

其他用户通过 npm 安装 `@flowingspring/dsh-voco` 后，使用硅基流动语音识别功能时，需要配置自己的 `SILICONFLOW_API_KEY`。当前插件已经支持从插件配置、进程环境变量和启动目录的 `.env` 文件读取密钥，但对于普通用户来说仍不够直观。

目前用户不需要、也不应该直接修改 npm 安装目录中的源码或配置文件。安装目录可能在升级或重新安装时被覆盖，也容易造成密钥泄露。

## 目标

在 DSH 设置页面为 dsh-voco 提供完整、易理解的 API Key 配置流程，让用户安装插件后可以直接完成配置、验证并开始使用。

期望体验：

1. 用户安装并启用插件。
2. 打开 DSH 设置中的 dsh-voco 配置页面。
3. 填写自己的硅基流动 API Key。
4. 点击“测试连接”。
5. 测试成功后保存配置并开始使用话筒。
6. 如果尚未配置，界面明确引导用户前往设置，而不是只显示“连接失败”。

## 计划功能

### 1. 设置页面

- 增加“硅基流动 API Key”输入项。
- 使用密码输入框，默认隐藏密钥内容。
- 提供显示/隐藏按钮，便于用户检查输入。
- 增加硅基流动 API Key 申请入口和简短说明。
- 标明该 Key 由用户自行申请，不随插件提供，也不会发布到 npm。
- 说明 Edge TTS 不需要 API Key，只有云端语音识别需要配置。

### 2. 测试连接

- 增加“测试连接”按钮。
- 使用低成本请求验证 Key 是否存在、格式是否有效以及服务是否可访问。
- 区分并展示常见错误：
  - 尚未填写 API Key；
  - API Key 无效或已过期；
  - 账户余额或服务权限不足；
  - 网络、代理或 DNS 异常；
  - 硅基流动服务暂时不可用。
- 测试过程中显示加载状态，避免用户重复点击。

### 3. 缺少配置时的引导

- 用户点击话筒但尚未配置 Key 时，不再笼统显示“语音连接失败”。
- 显示明确提示，例如：

  > 尚未配置硅基流动 API Key，请前往 dsh-voco 设置完成配置。

- 如果 DSH 支持页面跳转，提供“前往设置”按钮。
- 网络错误、鉴权错误和插件内部错误应使用不同提示，方便用户自行判断。

### 4. 配置读取与兼容策略

保留现有配置方式，避免影响已经在使用插件的用户。建议读取优先级为：

1. DSH 中保存的 `voice-local.apiKey`；
2. 环境变量 `SILICONFLOW_API_KEY`；
3. DSH 用户目录下的稳定 `.env` 文件；
4. 为本地开发保留项目目录 `.env` 兼容逻辑。

实施前需要确认：

- DSH 是否会根据插件的 `Config` Schema 自动生成设置表单；
- `cordis.patch.yml` 更新现有 `voice-local` 节点的准确写法；
- DSH 是否提供安全凭据存储能力；
- DSH 用户目录下适合保存 `.env` 或插件配置的稳定位置。

如果 DSH 提供系统凭据库或加密存储，应优先使用；否则需要明确提示用户，本地配置文件中的密钥可能以明文保存。

## 安全要求

- 不在源码、默认配置、示例文件、测试快照或日志中写入真实 API Key。
- 不把任何用户密钥打包进 npm 发行包。
- 不在错误信息、调试日志或遥测数据中输出完整密钥。
- 日志如需定位问题，只显示脱敏后的末尾少量字符。
- `.env` 和本地密钥文件必须被 Git 忽略。
- README 中只使用明显的占位符，例如 `sk-your-api-key`。
- 卸载插件时说明本地密钥是否保留，以及如何手动清除。

## 文档更新

功能完成后同步更新中文和英文 README，至少包含：

- 为什么需要 API Key；
- 如何申请硅基流动 API Key；
- 设置页面配置步骤；
- 环境变量和 `.env` 的高级配置方式；
- 常见错误及排查方法；
- 密钥安全注意事项。

## 测试计划

- 未配置 Key 时显示正确引导。
- 设置页面能够保存和重新读取 Key。
- 密码输入框默认不显示明文。
- 测试连接能够区分成功、鉴权失败和网络失败。
- 配置修改后无需重装 npm 包即可生效；如果必须重启，应明确提示。
- 环境变量和现有 `.env` 用户升级后仍能正常使用。
- 日志、错误提示和构建产物中不出现完整 Key。
- Windows 下通过 DSH Web 和命令行启动均能读取正确配置。
- 插件升级或重新安装不会意外清除用户配置。

## 验收标准

- 新用户无需修改 npm 包文件即可完成配置。
- 从安装完成到首次成功使用话筒，有清晰可见的操作路径。
- 缺少 Key、Key 无效和网络异常能够得到不同且准确的提示。
- 旧配置方式继续可用，不破坏现有用户环境。
- npm 包、Git 仓库、运行日志中不包含真实密钥。
- README 中的配置说明与实际界面和行为一致。

## 建议实施顺序

1. 调研并确认 DSH 配置表单、配置持久化和安全存储能力。
2. 定义 API Key 配置 Schema 和读取优先级。
3. 实现设置页面及保存逻辑。
4. 实现测试连接与错误分类。
5. 优化话筒入口的缺少配置提示和设置跳转。
6. 补充自动化测试及安全检查。
7. 更新中英文 README。
8. 在本地和测试版本验证稳定后，再发布新的 npm 版本。

## 暂不包含

- 为用户代为申请或共享硅基流动 API Key。
- 在 npm 包中内置开发者自己的密钥。
- 自建统一代理服务并替所有用户承担语音识别费用。
- 在没有明确隐私说明的情况下上传或收集用户配置。
