# DSH-VOCO-20260830-06：主会话归档后子会话仍可访问

## 问题信息
- 发现日期：2026-08-30
- 发现会话或复现方式：归档语音主会话后，子会话仍可能出现在语音树中，或可通过任务卡片、侧栏旧入口直接打开
- 相关模块或代码：`packages/ui-voice/src/client/VoiceSessionMarkers.tsx`、`packages/ui-voice/src/client/VoiceNodeViews.tsx`、`packages/ui-voice/src/client/index.ts`
- 状态：处理中
- 验证情况：类型检查通过；13 个测试文件共 132 项测试通过；生产构建通过；`git diff --check` 通过；现有 Web 服务 `http://127.0.0.1:3080/` 返回 HTTP 200。新增父级归档、恢复和导航 guard 回归覆盖。

## 问题描述
archive-manager 的归档集合只记录用户操作时传入的单个会话 ID，不会自动把 `origin === "subagent"` 的后代加入集合。若语音主会话被归档，子会话仍可能被 dsh-voco 当作可见、可导航的独立会话，形成主会话已收纳而子会话仍可访问的不一致状态。

## 证据与复现
宿主 `workspace.archiveSession(sessionId)` 只追加传入 ID 到 `archivedSessionIds`。宿主 session list 摘要仍保留 child 的 `parentId`，导航服务也能为 child 提供父子地址，因此可以在客户端判断归档祖先，而无需修改第三方 archive-manager。

## 影响
- 主会话归档后，语音侧栏展开树可能继续显示子会话。
- 任务卡片的“查看后台详情”可能仍可用。
- 通过旧任务卡片或直接导航入口可能重新打开已收纳的子会话。

## 原因判断
dsh-voco 原先只判断 `archivedSessionIds.has(childId)`，没有沿 `parentId` 或导航地址向上继承归档状态；导航入口也没有读取 workspace 归档快照。

## 解决方案
新增纯函数沿 session summary 的 `parentId` 链判断“自身或任一祖先是否已归档”，在缺少 summary 时使用宿主 `navigationAddress` 或当前语音父会话作为 fallback。该判断只影响 dsh-voco 的显示和导航，不扩展或改写第三方归档集合。

- 子会话树过滤自身及任一归档祖先。
- 任务卡片在目标 child 或其祖先归档时禁用打开按钮。
- 侧栏 child 与任务卡片的两个运行时 `openSession` 入口统一拒绝已归档链路。
- 恢复主会话只需从归档集合移除主 ID，子会话即可自然重新显示。

- 2026-08-30：新增 `session-archive.ts` 祖先链判断，接入 child 过滤、任务卡片导航状态和运行时打开 guard；恢复 `workspaces` 作为只读模块依赖声明。
- 2026-08-30：新增父会话归档后 child 隐藏、任务卡片禁用、运行时拒绝打开及恢复后可重新显示的回归测试；13 个测试文件共 132 项通过，类型检查、生产构建和 `git diff --check` 均通过。

## 后续低优先级优化
- 若宿主未来提供“归档祖先”或有效归档状态的统一 selector，优先改用宿主 selector，减少客户端重复遍历。
- 删除主会话的级联行为继续由 archive-manager 官方删除 RPC 负责，本问题不在 dsh-voco 重复实现删除事务。
