# DSH-VOCO-20260831-03：静音来源长按 PTT 未打开麦克风

## 问题信息

- 发现日期：2026-08-31
- 发现方式：实现严格 PTT 控制器回归测试时覆盖“已连接且已静音”来源
- 相关模块或代码：`packages/ui-voice/src/client/voice-controller.ts`
- 状态：已解决
- 验证情况：控制器测试、全量测试、类型检查和生产构建均通过；用户完成真实页面验收，未发现问题

## 问题描述

从已连接且已静音状态开始长按时，控制器会发送 `audio.push-to-talk.start`，但没有将浏览器 `MediaStreamTrack.enabled` 恢复为开启。该次 PTT 因而不会上传麦克风 PCM，松手时只能提交空片段。

## 原因判断

PTT 的来源静音状态被用于结束后的恢复，但开始阶段只处理了服务端手动采集模式，没有把输入轨道临时解除静音。未连接来源长按建立连接时也存在同一风险，因为它以静音状态完成连接。

## 解决方案

在 `VoiceController.activatePushToTalk()` 中，发送手动采集开始帧前调用 `setInputMuted(false, false)`：临时打开输入轨道且不发送额外 `audio.commit`。结束 PTT 后仍根据来源状态恢复静音或免提，并由独立的 `commitAudio()` 保证只提交一次。
