## 原因判断
当前 child 行由 `VoiceSessionMarkers` 直接创建，宿主或 archive-manager 的 `SessionNodeItem` 不会为它提供 React 菜单。`@michengai/dsh-archive-manager@0.1.19` 通过 `cordis.patch.yml` 禁用官方 `ui-workspace` 并注册自己的 `sidebar.workspaces` renderer；归档、删除是该 renderer 注入给其内部 `SessionNodeItem` 的动作，不是所有会话行自动继承的全局 action registry。因此主会话有归档/删除，语音插件在 DOM 中追加的 child 行不会被插件自动发现。

archive-manager 的永久删除公开边界是它挂载的 `remote.workspaceRegistry.deleteSession(sessionId)`。该 RPC 进入 archive-manager 的完整后端删除路径，负责 live session、会话目录、workspace 关联、归档标记、projection cache、spill、tombstone/index 和 descendants 清理，不应在 dsh-voco 复制实现。dsh-voco 需要声明 `remote` 注入，才能在严格 Cordis context 中探测并调用该能力。

删除能力接通后的首次用户验收表明删除正常、归档无效。真实 HTTP 反馈循环确认裸 UUID 子会话可被宿主 `workspace.archiveSession` 成功归档并写入 `workspace.json`，archive-manager 的 `workspaceRegistry/unarchiveSession` 也可完整恢复，排除了子会话 ID、宿主归档实现和持久化层。实际根因是客户端直接访问 `ctx.workspaces.archiveSession`，但模块级 Cordis `inject` 遗漏了 `workspaces`；严格上下文拒绝该未声明服务访问，而菜单原先仅将 rejection 写入控制台，所以界面表现为无响应。删除路径使用已声明的 `remote`，因此不受影响。

归档动作修复后的第二次用户验收表明归档集合和“全部恢复”正常，但设置页列表为空。浏览器复现确认持久化集合含 1 个 child ID 时页面仍显示“暂无已归档会话”。archive-manager `0.1.19` 的 `deriveArchivedGroups` 显式执行 `session.origin === "subagent"` 时 `continue`，主动丢弃 child 摘要；而“全部恢复”直接消费权威 `archivedSessionIds`，所以两者表现不一致。宿主 `session.list` 在 child 已归档时仍提供标题、更新时间、父会话、origin 和 cwd，证明无需扩展元数据 RPC。

截图中的深灰卡片来自宿主父 `SessionNodeItem` 的 HoverCard；大块白色提示来自 child 自身的 `title` 属性。时间错位则是因为透明状态的菜单按钮仍占据 24px 布局宽度。

## 解决方案
child 行保留语音专属的层级与导航，操作入口使用官方 `@deepseek-ai/dsh-client-ui-primitives` 的 `Menu`、`Modal`、`Button` 和官方会话图标。菜单固定提供重命名、分叉；运行时探测到 archive-manager 的 `remote.workspaceRegistry.deleteSession` 后增加 danger 状态的删除项。当前 Web profile 安装该插件，因此用户可见的子会话菜单为 3 项。插件不存在时隐藏删除项，dsh-voco 不把社区插件设为硬依赖。

子会话不再暴露归档菜单，也不再向 `childActions` 注入归档动作。dsh-voco 仅声明 `workspaces` 并读取宿主共享的 `archivedSessionIds`，用于显示层兼容外部归档状态；实际归档操作仍完全由主会话和 archive-manager 负责。

永久删除前保存 child 的 parent address，删除 RPC 成功后刷新顶层 session list 和父级 subagent catalog，避免已删除行因旧 catalog 暂时残留。时间列继续复用主会话的紧凑相对时间规则，并在 child hover 或菜单打开时隐藏；菜单触发器不设置浏览器 `title`，child 行继续抑制宿主父行 HoverCard。

撤销对 archive-manager 源码的适配修改：Web profile 恢复 npm 官方 `@michengai/dsh-archive-manager@0.1.19`，删除本轮临时克隆，不在第三方插件中处理子会话归档展示。

## 后续低优先级优化
- 若宿主未来提供可复用的 child-row renderer 或菜单 action slot，优先切换到宿主原生 renderer，减少 DOM 装饰逻辑。
- 若 archive-manager 后续提供公开的 session-action UI capability（包含确认框状态），优先由它直接拥有 child 删除交互；当前版本只公开删除 RPC，确认 UI 使用与其主会话相同的官方 primitives。
- 重命名当前使用轻量输入提示；可在宿主开放通用会话重命名对话框调用后统一交互样式。
- jsdom 无法完整复现宿主 React HoverCard 的真实 portal 生命周期，HoverCard 是否在集成环境中彻底消失仍需真实侧栏 hover 验收。
- 官方重命名入口由 `ui-workspace` 内部的 `WorkspaceBrowser` Modal 回调驱动，当前公共插件 API 未暴露该 Modal；子会话暂时沿用轻量输入提示触发同一 session rename 能力。
