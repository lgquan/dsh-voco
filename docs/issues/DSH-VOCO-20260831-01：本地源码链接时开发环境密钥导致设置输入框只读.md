# DSH-VOCO-20260831-01：本地源码链接时开发环境密钥导致设置输入框只读

## 问题信息

- 发现日期：2026-08-31
- 复现方式：将 `packages/voice-app` 以 `link:` 方式安装到 DSH web profile，从工作区父目录启动 `dsh web`，打开“设置 → 插件 → 插件配置 → 语音助手（Voco）”
- 相关模块：`packages/voice-local/src/index.ts`
- 状态：已解决
- 验证情况：自动化测试、类型检查、发行构建和真实 DSH 设置页验证通过

## 问题描述

本地源码仓库根目录存在用于开发的 `.env` 时，`voice-local` 会根据构建产物位置主动查找并调用 `loadEnvFile()`。这会把开发密钥提升为当前 DSH 进程的环境变量。DSH 官方 credentials provider 按设计将继承的进程环境变量视为优先且只读的来源，因此 Voco 设置卡虽然显示“已配置密钥”，API Key 输入框却被禁用，无法测试设置页写入。

## 证据与复现

真实页面初次验证结果：

- Voco 卡片已出现在原厂插件配置列表末尾；
- 展开后字段类型为 `password`，值长度为 `0`，没有回传明文；
- 页面显示“已配置密钥。”；
- 输入框 `disabled: true`。

DSH credentials 的来源优先级中，继承的进程环境变量高于可写凭据文件。问题不是凭据 API 或卡片逻辑错误，而是插件在 credentials 服务已经存在时仍自行调用 `loadEnvFile()`，改变了官方凭据层对来源的判断。

## 影响

NPM 安装包通常不包含仓库 `.env`，因此普通用户不受包目录文件影响；但本次要求使用本地源码链接验收，正好触发该行为。开发者也无法在保留仓库 `.env` 的同时测试设置页保存体验。

## 解决方案

当 DSH 官方 `credentials` 服务存在时，由它独占环境变量、DSH 凭据文件、启动目录 `.env` 和用户目录 `.env` 的分层解析，`voice-local` 不再调用 `loadEnvFile()`。只有在宿主没有 credentials 服务的兼容场景中，才继续执行原有项目 `.env` 加载逻辑。

## 处理记录

- 保留插件配置中的 `apiKey` 最高优先级，兼容已有显式配置。
- 保留无 credentials 宿主的 `process.env` 和项目 `.env` 兜底。
- credentials 存在时，每次新建语音连接通过 `credentials.resolve('SILICONFLOW_API_KEY')` 解析，设置页保存后重新开启或重连语音即可生效。
