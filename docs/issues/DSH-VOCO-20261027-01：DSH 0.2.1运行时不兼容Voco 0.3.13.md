# DSH-VOCO-20261027-01：DSH 0.2.1 运行时不兼容 Voco 0.3.13

## 问题信息

- 发现日期：2026-10-27
- 复现方式：在 DeepSeek Harness CLI `0.2.1-rc.2` 的 `web` profile 中加载 `@flowingspring/dsh-voco@0.3.13`
- 相关模块或代码：根 `package.json`、`cordis.patch.yml`、`packages/voice-assistant`、`packages/voice-local`、`packages/voice-web`、`packages/ui-voice`
- 状态：已解决
- 验证情况：全部 140 项自动化测试、类型检查、peer 检查、构建和发布包检查通过；修复后的 tarball 已在独立 CLI `web` profile 中完成安装、宿主启动、浏览器启动、设置页和 WebSocket 路由验收

## 问题描述

DeepSeek Harness 命令行版已使用 `0.2.1-rc.2`，桌面应用外壳为 `0.2.1-rc.3`，桌面插件运行核心仍为 `0.2.1-rc.2`。Voco 最新发布版 `0.3.13` 的 peer dependency 仍限定在 DSH `0.1.1-rc.x` 系列，因此新版插件兼容门禁拒绝安装。绕过门禁后，Voco 仍会因已移除或迁移的运行时导出而加载失败。

## 证据与复现

桌面插件管理器日志：

```text
C:\Users\QUAN\.dsh\profiles\desktop\.plugin-manager\logs\operation-DzHP1M\pnpm.log
```

日志明确报告：

```text
Plugin @flowingspring/dsh-voco@0.3.13 is incompatible with dsh 0.2.1-rc.2
```

后续强制安装路径还产生真实导入错误：

```text
voice-assistant: failed to import: SyntaxError: The requested module
'@deepseek-ai/dsh-session' does not provide an export named 'snapshotJsonValue'
```

本机 `@deepseek-ai/dsh-session@0.2.1-rc.2` 的实现已从 `@deepseek-ai/dsh-util-values` 内部导入 `snapshotJsonValue`，但不再从自身入口导出它；Voco `0.3.13` 的 `lib/plugins/voice-assistant.js` 仍从 `@deepseek-ai/dsh-session` 导入。

桌面 profile 当前没有在 `package.json` 的 dependencies 或 bundle stack 中启用 Voco。`node_modules/@flowingspring/dsh-voco` 虽残留 `0.3.13` 文件，但不是有效安装状态。

修复后的 tarball 首次隔离启动还暴露了两个仅靠类型检查无法发现的运行时契约变化：

```text
voice-web (@flowingspring/dsh-voco/voice-web): pending (waiting for service: webRuntime)
```

DSH `0.2.1-rc.2` 已将旧 `webRuntime` 拆分为路由服务 `webServer` 和启动参数服务 `webStartup`。修正后宿主无 pending 项。浏览器端随后报告 Voco client 激活失败；对 Cordis Fiber 的隔离诊断得到：

```text
Error: cannot get property "remote.credentials" without inject
```

新版 Cordis 要求使用 `ctx.remote.credentials` 的 client 插件显式声明嵌套服务 `remote.credentials`。补齐声明后浏览器端无启动错误。

## 影响

- NPM 上现有的 Voco `0.3.13` 无法在 DSH `0.2.1-rc.2` 的新版插件兼容门禁下正常安装。
- 即使授予精确版本豁免，旧发布包仍会在语音助手模块导入阶段失败，不能通过豁免安全解决。
- 当前源码和本地构建产物已兼容；市场用户仍需等待包含本修复的新版本发布。

## 原因判断

DSH 从 `0.1.1-rc.x` 升级到 `0.2.1-rc.x` 后调整了包图、公开 API、Web 服务和 client 服务注入规则。Voco 的 peer dependency 范围、Session/Persistence API、Agent preset、UI slots、settings、workspace、credentials 以及 Web patch 尚未整体迁移；旧构建产物还可能把已删除的 invariant 模块继续带入发布包。

## 解决方案

1. 将 DSH peer dependency 升级到 `^0.2.1-rc.2`，构建和测试依赖精确固定为 `0.2.1-rc.2`，不使用版本豁免掩盖不兼容。
2. 迁移 Session、Persistence、Agent preset、UI、Credentials、Workspace 和自定义消息来源等新版 API，删除已移除包及旧 invariant 入口。
3. 将 `voice-web` patch 改为注入 `webServer` 与 `webStartup`，并从 `ctx.webStartup.trustedHosts` 读取可信主机。
4. 为 client 显式声明 `remote.credentials`，确保 Cordis 能合法读取凭据远程服务。
5. 构建前清理根 `lib`，防止旧产物混入 tarball；用分发契约测试锁定包图、公开入口和运行时 patch。
6. 在独立 CLI `web` profile 中安装实际 tarball，验证宿主、浏览器 UI、设置页及 `/voice` WebSocket 路由。
