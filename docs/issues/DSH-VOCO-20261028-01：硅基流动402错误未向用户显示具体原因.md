# DSH-VOCO-20261028-01：硅基流动 402 错误未向用户显示具体原因

## 问题信息

- 发现日期：2026-10-28
- 发现会话或复现方式：在正式 CLI `web` profile 中使用 `@flowingspring/dsh-voco@0.3.14`，用户启动语音后看到“语音连接失败”
- 相关模块或代码：`packages/voice-local/src/siliconflow-asr.ts`、`packages/voice-local/src/node-backend.ts`、`packages/ui-voice/src/client/voice-controller.ts`、`packages/ui-voice/src/client/VoiceOverlay.tsx`
- 状态：待方案确认
- 验证情况：实际 `/voice` WebSocket 重放已两次稳定进入 `ready`，提交合成 PCM 后由硅基流动返回 HTTP `402 / code 30001 / account balance is insufficient`；用户充值后已确认语音识别、文字发送和 Agent 回复恢复正常。后续无法朗读回复是独立的 Edge TTS 问题 `DSH-VOCO-20261028-02`

## 问题描述

DSH 和 Voco `0.3.14` 可以正常加载，`/voice` WebSocket 也能建立连接并返回 `ready`。但当前硅基流动凭据对应的账户在提交 ASR 请求时返回余额不足。插件把后端失败发送为 `transcription.failed`，而浏览器控制器没有处理该事件，也没有在 `VoiceClientSnapshot` 中保留错误详情；用户界面只具备泛化的“语音连接失败”状态文案，无法直接判断是余额、凭据、网络、麦克风还是 WebSocket 故障。

发现时已确认 ASR `402`，充值后识别链路随即恢复，证明余额不足是当时 ASR 失败的直接原因。现有前端仍会忽略 `transcription.failed`，错误详情呈现缺口尚未实施修复，因此文档继续保持 `待方案确认`。

## 证据与复现

正式服务运行于 `127.0.0.1:3080`。不读取麦克风、不输出凭据的 WebSocket 探针使用当前完整 DSH 会话 ID，依次发送：

1. 建立 `/voice?sessionId=...` 连接并等待 `ready`。
2. 发送 `audio.push-to-talk.start`。
3. 发送 0.5 秒、16 kHz、PCM16 的合成音频。
4. 发送 `audio.commit`。

第一次完整事件序列：

```text
ready
transcription.started
transcription.failed: SiliconFlow ASR returned 402:
{"code":30001,"message":"Sorry, your account balance is insufficient","data":null}
```

收紧后的同一路径探针在不足 1 秒内再次稳定失败：

```text
FAIL SiliconFlow ASR returned 402:
{"code":30001,"message":"Sorry, your account balance is insufficient","data":null}
```

代码证据：

- `NodeSpeechBackend` 在 ASR 请求失败时发出 `transcription.failed`。
- `VoiceController.handleEvent()` 处理 `transcription.started`、`transcription.updated` 和 `transcription.completed`，但没有处理 `transcription.failed`。
- `VoiceClientSnapshot` 只保存状态，不保存可展示的错误码或错误消息。
- `VoiceOverlay` 在 `error` 状态固定显示 `overlay.error`，中文为“语音连接失败”。

## 影响

- 当前硅基流动账户无法完成语音识别，真实语音提交必然失败。
- 用户不能从界面区分余额不足和连接故障，容易反复重试或误判为插件兼容问题。
- README 将当前 ASR 模型描述为免费，但没有说明账户仍可能受到余额或额度门槛限制。

## 原因判断

已确认的直接运行原因是硅基流动账户余额不足，上游明确返回 HTTP `402`。恢复服务的最短路径是为该账户补充可用余额/额度，或在 Voco 设置中保存另一个具有可用额度的 `SILICONFLOW_API_KEY`。

插件侧另有独立的错误呈现缺口：结构化的 `transcription.failed` 没有进入可见状态，泛化错误状态也没有携带失败原因。用户看到的精确“语音连接失败”是否还包含浏览器端第二个错误，需根据失败发生时机或浏览器控制台进一步确认。

## 解决方案

1. 用户侧先确认硅基流动控制台余额/额度，充值或替换为有可用额度的 Key，然后用同一 ASR 探针验证从 `transcription.failed` 变为 `transcription.completed`。
2. 若错误在点击麦克风后、尚未说话时立即出现，继续采集浏览器控制台或权限状态，单独排查 `getUserMedia`、AudioWorklet 和 WebSocket 传输。
3. 插件侧可让 `VoiceClientSnapshot` 保存经过脱敏的错误类别与用户可读消息，显式处理 `transcription.failed`，区分余额不足、凭据无效、网络失败和麦克风权限失败。
4. README 补充“模型免费状态以平台为准，账户仍需满足平台的余额/额度要求”，避免把免费模型等同于任意账户都可零余额调用。
