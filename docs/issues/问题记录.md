## DSH-V-001：语音前台对项目事实直接回答，未委派后台任务读取项目资料

### 基本信息

- **发现日期**：2026-08-30
- **发现会话**：`session-5d340fa2-ea5a-410d-9d95-20080e862903`
- **工作区**：`C:\Users\QUAN\Desktop\PPT\02_项目_临床试验患者入组智能筛查系统`
- **相关代码**：`packages/voice-assistant/src/index.ts`
- **当前状态**：处理中；方案已确定，第一版代码已实施，等待真实语音回归
- **是否已修复**：部分修复；本地测试和构建已通过，尚未完成真实语音场景验收

### 问题描述

在语音交流的 `frontend-agent` 模式下，第一次询问“介绍一下这个项目吧”时，系统正确创建了后台任务，并读取了项目资料。

但在之后继续询问项目规则链、后处理和置信度修正时，前台多次直接生成回答，没有重新委派后台任务，也没有读取项目文件。这样会把上一轮回答当成事实来源继续推演；如果上一轮存在错误，后续回答可能沿着错误继续展开。

### 日志证据

目标语音会话中：

1. `seq=10`：用户提出“介绍一下这个项目吧”。
2. `seq=14`：创建后台任务 `2ed9ddb6-dd6e-4818-9bf9-e058b8a0ac19`。
3. 对应后台 Agent Session 为 `session-996c9afb-6e39-4a70-8be6-ee84b7a14388`；其第 1 轮调用了 `pwsh`、`glob` 和 `read`，实际读取了项目目录及 `临床筛查PPT.md`。
4. `seq=26、30、34、38、42` 的后续项目追问之间，没有新的 `voice/task-delegated` 事件；后台 Agent 第 2 轮也没有 `tool/call`。
5. `seq=36、40、44` 的回答把“置信度修正”说成“根据规则命中结果调整”。
6. 用户在 `seq=46` 明确质疑后，`seq=47` 才再次创建后台任务；后台结果在 `seq=54` 纠正为“根据证据完整性和不确定表达调整”。

因此，可以确认：后续错误回答至少没有经过新的项目文件读取，主要依赖已有对话上下文和前台模型生成。

### 影响

- 项目事实、实现细节、数字和文档口径可能被当成普通闲聊处理。
- 前台模型可能复述或放大上一轮回答中的错误，而不是回到项目资料核对。
- 用户无法从语音表现判断当前回答是否经过项目文件验证。
- 对需要可追溯、可复核的项目介绍和面试准备场景，事实可靠性不足。

### 初步原因判断

当前路由提示词允许以下内容选择 `chat`：

- 普通寒暄、日常对话；
- 无需外部事实或工具即可可靠回答的稳定知识。

同时，代码规定只有路由结果为 `delegate` 时才创建后台任务；`chat` 结果会直接播报前台模型的 `reply`。模型可能把“基于刚才介绍继续解释”误判为上下文聊天，而没有识别出问题仍然属于项目事实核对。

需要区分两类“记忆”：

- 前台确实能看到最近的语音对话，因此可能沿用之前后台读取后生成的介绍文本；
- Workspace Memory 是摘要/检索记忆，不等同于重新读取项目原文件，也不能保证包含最新或完整事实。

目前没有证据证明每次错误都完全来自模型训练记忆，但可以确认对应回答没有新的文件读取链路。

### 解决思路（待讨论）

保持“前台自然对话 + 后台任务执行 + 结果改写/TTS”的总体架构，不要求每句语音都委派。重点收紧项目事实的 `chat` 边界：

1. 普通寒暄、复述、简单确认，以及完全基于当前已验证结果的自然衔接，可以继续走 `chat`。
2. 涉及“这个项目/项目文件/文档/PPT/代码/具体数字/实现细节/按资料核对”的问题，默认走 `delegate` 并读取相关文件。
3. 用户提出纠错、质疑、要求确认，或问题包含陌生、不确定、可能过时的事实时，必须走 `delegate`。
4. 后台结果仍由前台改写成简短口语播报，避免把完整文档内容直接读给用户。
5. 仅靠提示词收紧只能降低误路由概率；如该要求必须稳定成立，后续可考虑增加确定性的项目事实触发规则或 `groundingRequired` 路由约束。

### 验证计划（方案确认后执行）

- 使用“这个项目的规则链有几层？”、“PPT 里怎么写的？”、“你刚才说的是否准确？”等项目事实问题进行回放。
- 检查是否出现 `voice/task-delegated`，以及后台 Session 是否出现 `read`/搜索工具调用。
- 检查普通闲聊是否仍保持直接、短句、低延迟，不被强制委派。
- 检查同一轮中先简短确认、再后台读取、最后口语化播报的完整链路。
- 对修复前后分别记录错误回答率、委派率、文件读取率和语音延迟。
