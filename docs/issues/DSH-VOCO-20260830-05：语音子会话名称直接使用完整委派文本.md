# DSH-VOCO-20260830-05：语音子会话名称直接使用完整委派文本

## 问题信息
- 发现日期：2026-08-30
- 发现方式：展开语音会话的子会话列表，委派任务名称直接显示完整请求，标题过长
- 相关模块或代码：`packages/voice-assistant/src/index.ts`、`packages/voice-assistant/tests/assistant.spec.ts`
- 状态：处理中
- 验证情况：后端集成回归测试通过；类型检查、13 个测试文件共 130 项测试、生产构建和 `git diff --check` 全部通过。`http://127.0.0.1:3080/` 返回 200 且启动终端无错误，待用户使用新委派 child 做真实页面验收

## 问题描述
主语音会话会根据第一条有效请求自动生成不超过 12 个汉字的标题，但委派 child 的 `subagent/descriptor.label` 直接使用完整任务请求，导致侧栏子会话名称明显过长。

## 证据与复现
创建 child 时，`createTaskAgent` 将传入的 `label` 最多截到 160 个字符后写入首个 `subagent/descriptor`。宿主子会话目录以该 descriptor 的 label 为持久化身份来源，不会自动用主会话标题逻辑替换。

回归场景使用长请求“请帮我全面检查这个项目中的所有依赖版本并报告需要升级的内容”。修复前 child descriptor 保存整段请求，而期望标题生成器输出“检查项目依赖”；委派给 Agent 的任务正文仍必须保持原文。

## 原因判断
主会话已有 `generateVoiceSessionTitle`，但它只在用户语音转写结束时作用于来源 session。child 创建路径没有调用标题生成器，并把任务正文和侧栏展示标签当成同一个字段。

## 解决方案
复用主语音会话的 LLM 标题提示、清洗规则和 12 字上限，将逻辑拆成候选标题生成与 session title 写入两步。创建新 child 时先生成标题，再将同一候选值写入首个 `subagent/descriptor.label` 和 child 正式 session title；完整请求只作为 Agent 用户消息发送，不被缩短。

存在宿主 `sessionTitle` 服务时使用 LLM 自动生成；服务不可用时不额外调用 LLM，按相同清洗和 12 字上限确定性回退。continuous 模式只在首次创建、模型切换重建或上下文轮换产生新 child 时命名，复用现有 child 时不重复改名。通过路由委派时标题依据用户原始请求，而不是包含 grounding 等内部上下文的扩展提示。

标题生成与 Agent session 创建并行执行，避免把两段等待串联；两者完成后才写入首个 descriptor。宿主将首个 `subagent/descriptor` 视为既有 child 的持久化身份，因而本修复只作用于之后新建或轮换出的 child，不改写历史 child。
